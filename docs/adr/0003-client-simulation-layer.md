# ADR-0003: Temporary client-side simulation layer

- **Status:** Accepted (temporary; to be superseded by F-020)
- **Date:** 2026-11-21
- **Documentation mode:** Retroactive
- **Decision owners:** Project owner

## Context
The backend did not exist, but the UI and user journeys had to be designed, demonstrated, and reviewed.

## Decision
`App.tsx` holds auctions, accounts, favorites, notifications, and tickets in React state and mirrors them to `localStorage`. Pages access it only through `useAppContext()` (`AppContext` in `types.ts`). Support replies are generated by a timer and labelled "automatic (sample)".

## Alternatives considered
- Mock server (MSW/json-server): rejected as extra tooling for a short-lived stage.
- Waiting for the backend: rejected; it would block UI work and demos.

## Consequences
- **No security:** roles, rules, and "login" are enforceable by anyone using the browser console. Passwords are not checked.
- All browser users share notifications and tickets; all bids are recorded as the user «من».
- Business rules are duplicated in the browser and must be re-implemented and re-tested on the server (F-014).
- `AppContext` is the integration seam: F-020 replaces its implementation with an API client without rewriting pages.
